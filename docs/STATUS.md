独立 smaps 证明两版本都确实映射 **8192 KiB socket 抓包缓冲**；本机 cgroup/

占用。低负载 RSS/PSS 确实进入了约 11–12 MiB，而不是预先承诺。

高负载过期后 active/timers 都归零，三轮循环后 RSS 中位数 14.61 MiB，未回到初始

## 已发现并通过证据修正

- 最终 ACK 计入字节但不一定计入 duration；不是首尾包时间简单相减。
- 重组数据报只计一次 IP 长度；IPv4 非复制选项保留“最先观测片”的头长，逆序 60、顺序 64 bytes，确实是旧版行为。
- 分片必须在新包处理前过期；不是处理完过期尾片后再清理。
- 坏 L4 校验和可能生成 0/0 会话；坏 IPv4 头则更早丢弃。
- bare Zeek 仍有 IPIP/GRE/VXLAN 解封装；不把 bare 错当没有隧道能力。
- --check-config 已改为可读的秒数、规则及实际 IP，而非内部二进制数组。

## 尚未完成 / 未获接受的策略

1. **完整 TCP/Zeek 状态机不等价**：复杂序列窗口、非法 RST/异常 SYN、方向修正、计时器精确边界及特殊交互端口启发式仍需扩展差分。
2. **Geneve/GTP/Teredo/MPLS/PPPoE、特殊 GRE、active routing/jumbogram 等不支持**；截断/严重畸形/矛盾分片、资源耗尽当前非零退出，不把保留会话输出为假完整记录。旧版可能继续处理；这是开发期安全门，**不是已获同意的容错行为变更**。需决定继续补齐旧行为还是接受明确拒绝策略。
3. 无应用层分析；旧脚本声明的 analyzer-confirmation 超时扩展在其 bare 装载组合下的实际触发范围尚未验证，本实现无该路径。
4. 未验证：生产流量、原生 Linux/arm64/rootless、高突发/饱和吞吐、长期运行、大规模实网 TCP、任意封装/重叠组合、完整旧版本等价。
5. 捕获系统 dropped=0 不证明端到端无丢包；offload、接口选择、启动/停止窗口及输出反压仍会影响可见流量。
